yavs 0.19.0 makes the start of a testbench faster: long subprograms are optimised sooner, string helpers cost less in the interpreter, and the first run of a testbench with large bus procedures stays short.

- **Faster start of testbenches on library code:** long subprograms, such as a function of hundreds of statements or a long `if`/`elsif` chain, are optimised much faster on their first call.
- **Faster string and array parameters:** subprograms with string and other array parameters, such as logging and checking helpers, are called with less overhead in the interpreter.
- **Shorter first runs with `--tier-compile=wait`:** a process is no longer compiled together with the procedures that wait for it before they have run long enough to repay the compile.
- **Better profiles:** a process that waits inside a procedure has the work it does after the procedure returns counted for itself, so `yavs run --profile` and the default tier's choice of what to compile see where the time goes.
- **Cleanup:** the environment variable `YAVS_FIRST_ONLY`, which has had no effect since the LLVM tier was removed, is gone.

# Bug fixes

- A process that waits inside a procedure now has the work it does after that procedure returns counted for itself, not for the procedure: the busiest subprograms of `yavs run --profile` and the choice of what the default tier compiles see where the time really goes.

# Miscellaneous

- Long subprograms, such as a function with hundreds of statements or a long `if`/`elsif` chain, are optimised much faster when they are first called, so testbenches built on such library code start sooner.
- Subprograms with string and other array parameters, such as string, logging and checking helpers, are called with less overhead in the interpreter, so testbenches built on them simulate faster.
- The environment variable `YAVS_FIRST_ONLY`, which has had no effect since the LLVM tier was removed, is gone.
- With `--tier-compile=wait`, the first run of a test no longer compiles a process together with the procedures that wait for it before they have run long enough to repay the compile, so the first run of a testbench with large bus procedures stays short; `YAVS_AUTO_WAIT_TREE` tunes it.
