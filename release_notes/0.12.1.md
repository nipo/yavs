yavs 0.12.1 is a bug fix release: it fixes subtype indications that use an attribute of an indexed object name, makes deferred constants with an unconstrained subtype work with their attributes in package bodies, and states the 64-bit minimum literal rule in the error it gives.

# Bug fixes

- Correction: yavs 0.4.0 to 0.6.0 accepted the literal `-9223372036854775808` (and `-9223372036854775808 fs`) as the 64-bit minimum. That was a bug: the standard makes the literal an error before the minus applies (LRM 9.5, 9.3.6), and it has been rejected since 0.7.0. The error now names the literal and says to write `-9223372036854775807 - 1` (`-9223372036854775807 fs - 1 fs` for a physical type). [#214](https://github.com/ru551n/yavs/issues/214)
- A subtype indication can take the subtype of an object name whose prefix indexes an array before selecting a field, such as `variable v : a(0).v'subtype;` (also `'element`, in declarations and parameters); it was rejected with E0002. [#1067](https://github.com/ru551n/yavs/issues/1067)
- A deferred constant whose declaration constrains its subtype fully can be the prefix of `'range`, `'length`, `'left`, `'right`, `'high`, `'low`, `'ascending`, `'reverse_range`, `'subtype` and `'element` before its full declaration, for example in the parameter subtypes of a subprogram body in the package body. [#1072](https://github.com/ru551n/yavs/issues/1072)
- The attributes `'range`, `'reverse_range`, `'length`, `'left`, `'right`, `'high`, `'low`, `'ascending`, `'subtype` and `'element` of a deferred constant with an unconstrained subtype can now be used in a package body, in subprograms (bodies, parameter subtypes, variables) and after its full declaration, with the bounds of the full declaration's value. The package declaration and the declarations of the body before the full declaration still report `E1226`.
  A subprogram of a package body that reads the bounds of an unconstrained deferred constant and is called, to initialise a constant of the body, before the constant's full declaration is elaborated is now a run-time error (`E3009`) that names the constant and says to move the call below the full declaration, in every execution tier.
  The bounds of an unconstrained deferred constant of a generic package instantiated in an architecture, block or process, which read as 1, and such a declaration in a process, which was an internal error, now report that this is not implemented yet. [#1076](https://github.com/ru551n/yavs/issues/1076)

# Documentation

- The documentation now states what happens to a suite far over the compile cache limit: above about three times the limit, later runs are slower than the first, so such a suite is better split into several libraries. [#1034](https://github.com/ru551n/yavs/issues/1034)
- The conformance report's third-party code sheet now analyses a newer release of one of its libraries, including the test benches that release ships. [#1060](https://github.com/ru551n/yavs/issues/1060)
