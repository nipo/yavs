yavs 0.16.1 fixes block guards and a false multiple-sources error, and makes record registers, procedures with signal parameters, array functions and more IEEE operators faster.

- **Block guards:** a guard may read any signal attribute, such as `clk'event and clk = '1'`, and is evaluated again whenever a signal of its condition is active. (#1114, #1120)
- **Bug fix:** a process driving one element of an unresolved signal indexed by an array attribute of a constant is no longer reported as a second source of the whole signal.
- **Faster record registers:** record signals keep no history or per-element copy that nothing reads, and a whole record copied in compiled code is as fast as copying it field by field. (#1110, #1117, #1119)
- **Faster procedures and functions on arrays:** a procedure with signal parameters of an array type and a function on an array of vectors run close to the same loops written in the process. (#1121, #1122)
- **More native operators:** `?=` and `?/=` on `std_logic_vector`, and the Synopsys operators with a `std_logic` operand and their unary forms, run natively and in place in compiled code.




# Bug fixes

- A block guard may read any signal attribute, such as `clk'event and clk = '1'`, `'last_value`, `'stable` or `rising_edge(clk)`: such a design now elaborates, GUARD starts as its condition, and a guarded assignment under an edge guard assigns while that GUARD stays true. (#1114)
- A block guard is evaluated again whenever a signal of its condition is active, also for an assignment that keeps the value, so guards on `'event`, `'active` or `'last_event` and the guarded assignments under them follow such transactions. (#1120)
- A process driving an element of an unresolved signal indexed by an array attribute of a constant, such as `s(c'length + i)`, now drives only that element, instead of being reported as a second source of the whole signal.

# Miscellaneous

- A whole record signal of vector fields copied in compiled code (`s1 <= s0;`) is now as fast as copying it field by field. (#1110)
- Record signals and arrays of records whose history nothing asks for no longer keep it, so register pipelines built from records simulate faster; a hang or delta cycle limit report then gives the event times of the whole record. (#1117)
- Record signals whose fields nothing reads one element of no longer keep a per-element copy of their value, so register pipelines built from records simulate faster. (#1119)
- Procedures with signal parameters of array types, such as one stage of an adder tree written once and called for every stage, now simulate much faster, close to the same loops written in the process. (#1121)
- A function that works on the elements of an array of vectors, such as one stage of an adder tree on an array of `signed`, runs faster in compiled code, and so does an assignment of more than 64 logic elements at once. (#1122)
- The `+` and `-` of `std_logic_arith`, `std_logic_unsigned` and `std_logic_signed` with a `std_logic` operand, their unary `-` and `abs`, and the unary `+` of `std_logic_unsigned` and `std_logic_signed`, now run as native operations that compiled code computes in place on short vectors.
- The matching operators `?=` and `?/=` on `std_logic_vector` and `std_logic` run natively, also in compiled code, instead of element by element.
