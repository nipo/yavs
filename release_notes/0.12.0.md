yavs 0.12.0 is the debugger and coverage release: an interactive console, a much deeper VS Code extension and live waveforms in Surfer, joined by a static checker, a reworked coverage tool with state machines and combinations, and a much larger part of VHPI. **It has breaking changes: read the next section before you upgrade.**

# Breaking changes

Each of these needs something from you when you upgrade.

- **Rebuild your libraries.** The library format changed. A library written by an earlier yavs is refused with `L0004`: delete the library directory once and analyze its files again ([what yavs stores on disk](https://yavs.readthedocs.io/en/v0.12.0/on-disk.html#how-to-clear-them)). An instance or binding can now name an architecture that is analyzed later, so a missing one is an error at elaboration instead of at analysis. [#819](https://github.com/ru551n/yavs/issues/819) [#1044](https://github.com/ru551n/yavs/issues/1044)
- **Run your coverage again.** Coverage databases have a new format: rebuild them by running the simulations with this yavs. [#1020](https://github.com/ru551n/yavs/issues/1020)
- **Coverage kinds are opt in, and `--cov` changed meaning.** No kind is on by default. `yavs run --cov=LETTERS` turns coverage on and picks the kinds (`--cov=sbt`: `s` statement, `b` branch, `c` condition, `e` expression, `t` toggle, `f` fsm, `a` assert, `m` combination); `--cov-kind=statement,branch,toggle` is the long form. What bare `--cov` used to measure is now `--cov=sbt`. The database file is now `--cov-file=FILE`, default `yavs.ycov`. Bare `--cov` is error [`E0140`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#e0140), which lists the kinds and a command to copy, and an old `--cov=FILE` fails with a pointer to `--cov-file`. With vunit-yavs, `--yavs-cov` becomes `--yavs-cov=LETTERS`, and a simulation with coverage on and no kind fails before yavs starts, naming what to set ([flags](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#flags-for-yavs-run)). [#1020](https://github.com/ru551n/yavs/issues/1020)
- **`yavs cov report` prints something else by default.** A table of the kinds, a line per instance, then a count of what never ran and of what is excluded. Scripts that parse this text need a change, or better `--json`. `--uncovered`, `--tests`, `--exclusions` and the HTML report are unchanged. `--cobertura` now follows `--root` like every other report, so its paths are relative to the current directory unless you pass `--root`. [#1020](https://github.com/ru551n/yavs/issues/1020)
- **Paths are dotted.** Everything yavs writes now reads `Process tb.gen(1).u.p`: report and assert lines, runtime errors, diagnostics, `--print-hierarchy`, `--hang-report`, coverage reports and JSON output. A process without a label is called by what it is and where, such as `tb.clk <= ... (tb.vhd:17)`, instead of `tb._p0`. Scripts that parse `Process :tb:p` need the new form. `'path_name` and `'instance_name` keep their LRM colons, and colon paths are still accepted wherever you type a path. [#975](https://github.com/ru551n/yavs/issues/975) [#992](https://github.com/ru551n/yavs/issues/992)
- **Wrong lengths stop the run.** A record or an array of composites whose field or element has another length than its target used to be truncated silently: it now stops with a length error on every path, at analysis ([`E1405`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#e1405)) when the lengths are static. A design that passed because of this was simulating the wrong values. [#1005](https://github.com/ru551n/yavs/issues/1005)
- **Named aggregates in comparisons.** A named aggregate as an operand of a predefined operator takes the direction of the index subtype also when the array type is constrained, so a comparison such as `c = (0 => a, 1 => b)` can give another result than before, and `others` there is refused. [#1009](https://github.com/ru551n/yavs/issues/1009)
- **Native library hooks.** For authors of VUnit packages that use `native_library_hooks`: it now returns `elab_flags` instead of `run_flags`, so `--elaborate` loads the library too. Code that reads `run_flags` from the result needs the new key ([native libraries](https://yavs.readthedocs.io/en/v0.12.0/vunit.html#vunit-native-library)). [#120](https://github.com/ru551n/yavs/issues/120)
- **`yavs-gui` is gone.** It is no longer shipped and `yavs run --gui` no longer exists. Debug with any DAP client, such as VS Code, through `yavs run --dap` ([debugging](https://yavs.readthedocs.io/en/v0.12.0/debugging.html)). [#871](https://github.com/ru551n/yavs/issues/871)

# Debugger and console

- **A prompt for your simulation.** `yavs run --interactive` gives a `yavs>` prompt to run, step, examine, force, set breakpoints, restart at time 0 without recompiling and source files; `--do` runs the same commands as a script. They work in the VS Code Debug Console too ([interactive debugger](https://yavs.readthedocs.io/en/v0.12.0/interactive.html)). [#904](https://github.com/ru551n/yavs/issues/904)
- **Find out why a value is what it is.** [`drivers`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-drivers) lists each driver of a signal with its value and source line, the resolved value and any force. [`trace x`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-trace-x) follows an unknown value back to where it starts. [`describe`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-describe) gives type, bounds, resolution function, mode and declaration. [#944](https://github.com/ru551n/yavs/issues/944)
- **Find out where a run is stuck.** [`waits`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-waits) shows where each process stands and what it waits for; [`activity`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-activity) and [`asserts`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-asserts) summarise the run so far. [#944](https://github.com/ru551n/yavs/issues/944)
- **Look things up and look back.** [`find signals`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-find-signals) and [`find variables`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-find-variables) take a pattern, and [`examine NAME @ TIME`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-examine-at) reads a past value from the wave file being written. [#944](https://github.com/ru551n/yavs/issues/944)
- **Stop at a failed assertion.** [`break assert [SEVERITY]`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-break-assert) stops at a failed assertion or report of that severity and worse, with the stack intact. [#944](https://github.com/ru551n/yavs/issues/944)
- **Tab and "did you mean".** Tab at the prompt and in the Debug Console completes commands, subcommands, signals and variables in scope, fields, source files and a test runner's commands, and every name the debugger takes suggests what you may have meant. `exit` ends a session like `quit`. [#904](https://github.com/ru551n/yavs/issues/904) [#953](https://github.com/ru551n/yavs/issues/953) [#941](https://github.com/ru551n/yavs/issues/941)
- **New documentation.** A [step-by-step tutorial](https://yavs.readthedocs.io/en/v0.12.0/debugger-tutorial.html) with a runnable FIFO demo walks through a failing test in VS Code, with Surfer and at the console. The [console command reference](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html) covers every command, argument and error, and `help COMMAND` prints the synopsis of one. [#954](https://github.com/ru551n/yavs/issues/954) [#955](https://github.com/ru551n/yavs/issues/955) [#944](https://github.com/ru551n/yavs/issues/944)

# VS Code

- **Attach with no configuration.** Start a test with `python run.py lib.tb.test --yavs-debug`, set breakpoints in your own files and press F5 or run "yavs: Attach". Breakpoints and stack frames use your original files when the test runner compiles preprocessed copies ([debugging](https://yavs.readthedocs.io/en/v0.12.0/debugging.html#vs-code-with-a-test-runner)). [#902](https://github.com/ru551n/yavs/issues/902)
- **Add to Wave.** The context menu of the Variables and Watch views and of a selection in a VHDL file adds a signal or process variable to the waveforms of a Surfer session. [#876](https://github.com/ru551n/yavs/issues/876)
- **More from the context menu and the Breakpoints view.** "Show Drivers" on a signal, "Find Signals or Variables..." as a quick pick of matches to add to the wave, and exception breakpoint filters that stop at a failed assertion or report of a severity. [#944](https://github.com/ru551n/yavs/issues/944)
- **Easier to read.** Vectors show on one line in the Variables view, Watch and hover; Watch shows and takes dotted names and gives the nearest name for one that does not exist; the Threads view and Call Stack name a process by what it is and where, such as `tb.clk <= ... (tb.vhd:17)`. [#953](https://github.com/ru551n/yavs/issues/953) [#942](https://github.com/ru551n/yavs/issues/942)
- **Less to answer.** The extension no longer asks for a force mode, and a bit-like target takes `1` and `0101` without quotes in force, deposit, Set Value and break on value. [#953](https://github.com/ru551n/yavs/issues/953)
- **More to see.** Watch and hover take a field, element or slice and `.all`; the variable views expand access values and protected objects; shared variables have their own scope. The Debug Console shows the exit status at the end of a session. A launch that fails early shows its diagnostic. [#930](https://github.com/ru551n/yavs/issues/930) [#936](https://github.com/ru551n/yavs/issues/936) [#938](https://github.com/ru551n/yavs/issues/938) [#934](https://github.com/ru551n/yavs/issues/934)
- **Lint in the Problems view.** The `$yavs` problem matcher puts the diagnostics of a yavs task in the Problems view ([lint in VS Code](https://yavs.readthedocs.io/en/v0.12.0/lint.html#in-vs-code)). [#895](https://github.com/ru551n/yavs/issues/895)
- **Released with yavs.** The extension now carries the yavs version and every release attaches its `.vsix`. [#903](https://github.com/ru551n/yavs/issues/903)

# Waveforms

- **Live waves in Surfer.** `yavs run --surfer` shows the waveform in the Surfer viewer while the run writes it, starting Surfer or connecting to a running one. In a debug session the cursor follows the stops, breakpoints leave markers, the stopped process's signals are coloured and go to declaration opens the source. `wave add` and `wave cursor` work at the console, and `--yavs-surfer` and the VS Code `surfer` setting use it ([watching in Surfer](https://yavs.readthedocs.io/en/v0.12.0/waveforms.html#watching-in-surfer)). [#876](https://github.com/ru551n/yavs/issues/876)
- **Keep your signal list.** The signal list of the viewer survives a restart and a new run of a testbench, and the console has [`wave save`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-wave-save) and [`wave load`](https://yavs.readthedocs.io/en/v0.12.0/console-reference.html#console-wave-load) ([keep the signal list](https://yavs.readthedocs.io/en/v0.12.0/waveforms.html#keep-the-signal-list)). `wave add` takes a pattern and process variables too. [#944](https://github.com/ru551n/yavs/issues/944)
- **Variables are recorded while debugging.** A debug session that records a wave also records process and shared variables, without `--wave-variables`, so a variable you add later has its history from time 0. [#876](https://github.com/ru551n/yavs/issues/876)
- **The file agrees with the debugger.** At a stop the wave file reaches the stop time with the values the debugger shows, signals and variables, so a viewer and `examine NAME @ TIME` agree with the Variables view. [#961](https://github.com/ru551n/yavs/issues/961) [#965](https://github.com/ru551n/yavs/issues/965)

# Coverage

- **Measure what you ask for.** Eight kinds, chosen per run: statement, branch, condition, expression, toggle, and now `fsm`, `assert` and `combination`. Condition coverage now includes `wait until` conditions, and `--cov-kind=assert` adds the conditions of `assert` statements. [#1020](https://github.com/ru551n/yavs/issues/1020)
- **State machines.** `--cov-kind=fsm` counts, per instance, each state a machine reached and each transition it took, with merge, `rank`, reports and exclusions. A machine it cannot measure is warning [`W0120`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#w0120) and shows in the report ([state machines](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#state-machines)). [#1020](https://github.com/ru551n/yavs/issues/1020)
- **Condition combinations.** `--cov-kind=combination` counts each combination of the input values of conditions and logic expressions ([combinations](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#combinations)). [#883](https://github.com/ru551n/yavs/issues/883)
- **A report that tells you what to do.** The default report is a summary. `--detailed` is a debugging view per instance: a table per kind, the rows of each condition with what the other inputs must be, and for what never ran the source underlined, what is missing, a tip and the text that excludes it. `--below=PCT` keeps the instances under a percentage, worst first, so `--below=100 --detailed` shows what is left to do ([what is left to do](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#what-is-left-to-do)). Source paths are relative to the current directory or `--root`, and branch arms are named from the source (`if rst = '1'`, `when IDLE`). [#1020](https://github.com/ru551n/yavs/issues/1020) [#877](https://github.com/ru551n/yavs/issues/877)
- **Exclude in the source.** `-- yavs cov exclude 01: impossible handshake` waives a combination, `-- yavs cov exclude row -0-` one row of a condition, and `-- yavs cov exclude state spare` or `transition busy -> done` part of a state machine, all checked when the sources are analysed. A pattern may name its inputs, so a condition edited under the directive is an error that says what to write ([excluding in the source](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#excluding-combinations-and-rows-in-the-source)). A `-- coverage off` region can now leave out a single `when`, `elsif` or `else` arm. [#883](https://github.com/ru551n/yavs/issues/883) [#1020](https://github.com/ru551n/yavs/issues/1020) [#1042](https://github.com/ru551n/yavs/issues/1042)
- **Exclude from a file.** Exclusion files take `files` and `files_exclude` lists and plain directories, with the same matching as lint waivers, and `library`, `entity` and `process` rows. `--exclude` can be repeated, `--config FILE` holds a project's exclusion files, root and kinds ([configuration file](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#configuration-file)), `W0111` names the statement that probably replaced an excluded one, a rule whose items ran warns once (`W0114`), and `yavs cov report --exclusions` lists every rule with what it matched ([the exclusion report](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#the-exclusion-report)). [#1020](https://github.com/ru551n/yavs/issues/1020) [#883](https://github.com/ru551n/yavs/issues/883)
- **Gates and exports.** `--kind=LIST`, `--total` and `--fail-under=PCT`, or per kind `--fail-under=statement:90,branch:80`, make coverage a gate ([coverage in CI](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#coverage-in-ci)). `--json` writes a versioned report and `--lcov` an LCOV tracefile, checked with the lcov tool. `--sonarqube` follows the published format, but no real scanner has read it yet ([exports](https://yavs.readthedocs.io/en/v0.12.0/coverage.html#exports)). `yavs run --cov-embed-sources` stores the source text in the database, so the HTML report works with no checkout, and the text then travels with the database. [#877](https://github.com/ru551n/yavs/issues/877) [#1020](https://github.com/ru551n/yavs/issues/1020)

# Static checks

- **`yavs lint`.** Reports what can be proved wrong about a design before it is simulated: a process that can never suspend, a function that can fall through, unreachable statements, vector width mismatches, indexes out of range and division by zero. JSON, SARIF, JUnit, Code Climate and SonarQube reports are included. Advisory, experimental and policy rules (latches, multiple drivers, combinational loops, state machines, clock and reset crossings and more) run when a configuration asks for them, and `--facts` writes state machines and clock and reset domains as JSON ([static analysis](https://yavs.readthedocs.io/en/v0.12.0/lint.html), [rules](https://yavs.readthedocs.io/en/v0.12.0/lint-rules.html)). [#895](https://github.com/ru551n/yavs/issues/895)
- **What to check, and how.** `file_list` in `yavs-lint.yaml` names the files to check by path, directory or glob, and `--no-file-list` leaves it out. `rtl:` and `testbench:` hold rule sections per kind of file, told apart by `testbench_files`, `testbench_libraries`, the comment `-- yavs: testbench` or an inference from the code and the name. `suffixes` and `prefixes` take a regular expression after `re:`, and report nothing unless you set them. [#895](https://github.com/ru551n/yavs/issues/895) [#1002](https://github.com/ru551n/yavs/issues/1002)
- **Waivers.** A [waiver](https://yavs.readthedocs.io/en/v0.12.0/lint.html#waivers) can turn rules off for whole directories and file patterns, with `files_exclude` to take some back. A pattern that covers no file gets a warning. [#895](https://github.com/ru551n/yavs/issues/895)
- **A configuration that cannot mislead you.** Every YAML file yavs reads is checked against a declared list of keys, value types and nesting. In the lint files anything unknown is error [`E0134`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#e0134), every one listed with its line and a suggestion, so a misspelled `files` or `lines` cannot widen a waiver. `yavs lint` is a static analysis tool, not a style guide or formatter: a configuration written for a formatter must have those sections removed. [#895](https://github.com/ru551n/yavs/issues/895)

# Diagnostics

- **"Did you mean" everywhere.** A misspelled option, subcommand, option value, diagnostic code, lint rule, warning option, library, design unit, generic, enumeration literal, time unit or configuration key now gets a suggestion, and `--print-hierarchy`, `--verbose` tier notes, file modes and array bounds say what they mean in plain words. [#949](https://github.com/ru551n/yavs/issues/949)
- **Better answers to "why does this not finish".** A delta cycle limit error ([`E3002`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#e3002)) points at the other processes still running and at every signal still changing, with its value. [`--hang-report`](https://yavs.readthedocs.io/en/v0.12.0/cli-reference.html#cmdoption-yavs-run-hang-report) labels the statement each process stands at and lists every process that can still run. [#944](https://github.com/ru551n/yavs/issues/944)
- **Summaries at the end of a run.** [`--assert-summary`](https://yavs.readthedocs.io/en/v0.12.0/cli-reference.html#cmdoption-yavs-run-assert-summary) counts failed assertions and reports by severity and source line. [`--activity[=FILE]`](https://yavs.readthedocs.io/en/v0.12.0/cli-reference.html#cmdoption-yavs-run-activity) lists the processes that ran and the signals that changed most often. [#944](https://github.com/ru551n/yavs/issues/944)
- **Clearer "not supported".** Unsupported elaboration features and command combinations report [`E2199`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#e2199) and [`E0199`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#e0199) with their own explanations, and `E9999` is now only ever an internal error. [#868](https://github.com/ru551n/yavs/issues/868)
- **Analyzing a unit again.** The guide says what happens when a unit is analyzed again after a unit that depends on it: `run` analyzes the dependents again against the new version ([a unit analyzed again](https://yavs.readthedocs.io/en/v0.12.0/migrating.html#a-unit-analyzed-again)). [#1053](https://github.com/ru551n/yavs/issues/1053)
- **A manual that matches the tool.** A [command-line reference](https://yavs.readthedocs.io/en/v0.12.0/cli-reference.html) generated from the command line itself, an [index of every diagnostic code](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html) and a [registry of environment variables](https://yavs.readthedocs.io/en/v0.12.0/environment.html). The guide is now grouped by task, with new pages including a [project walkthrough](https://yavs.readthedocs.io/en/v0.12.0/project-walkthrough.html), [moving from another simulator](https://yavs.readthedocs.io/en/v0.12.0/migrating.html), [threads and the token server](https://yavs.readthedocs.io/en/v0.12.0/threads.html) and an [FAQ](https://yavs.readthedocs.io/en/v0.12.0/faq.html). The [release notes](https://yavs.readthedocs.io/en/v0.12.0/release_notes.html) are in the guide too. [#905](https://github.com/ru551n/yavs/issues/905) [#923](https://github.com/ru551n/yavs/issues/923)

- **Messages that name the right thing.** Two different types, subtypes or subprograms spelled alike are printed with their full paths, or where each is declared. Messages for what yavs does not implement yet name the construct, say it is a limitation of yavs and suggest what to do. `--threads=auto` says it is not implemented yet and what to give instead. [#1026](https://github.com/ru551n/yavs/issues/1026) [#996](https://github.com/ru551n/yavs/issues/996) [#997](https://github.com/ru551n/yavs/issues/997)
- **`yavs --version`** prints the copyright notice on a second line, under the unchanged version line. [#1039](https://github.com/ru551n/yavs/issues/1039)

# Faster large suites and designs

- **The compile cache holds a large suite.** A large suite in one library now gets the full benefit of the cache, where entries used to be replaced before they could be read. The limit is now the disk space of a library directory, so a large suite uses more disk ([on disk](https://yavs.readthedocs.io/en/v0.12.0/on-disk.html)). A suite far over the limit still runs slower warm than cold, as [#1034](https://github.com/ru551n/yavs/issues/1034) tracks. [#1027](https://github.com/ru551n/yavs/issues/1027)
- **An unchanged design finds its code.** It makes the same compiled code on every run, so warm runs reuse it instead of storing another copy, and the store of a large suite takes less disk. It still grows for some runs as functions become hot enough to compile for the first time ([on disk](https://yavs.readthedocs.io/en/v0.12.0/on-disk.html)). [#1035](https://github.com/ru551n/yavs/issues/1035)
- **Less to elaborate.** Signal arrays used as large memories and very large selected assignments and case statements elaborate and start much faster, with less memory, and a clocked process that reads its clock through an alias runs only on its edge. [#1001](https://github.com/ru551n/yavs/issues/1001) [#1008](https://github.com/ru551n/yavs/issues/1008)

# VHPI

Plugins can now see and do much more ([VHPI](https://yavs.readthedocs.io/en/v0.12.0/vhpi.html#at-a-glance)):

- **Statements.** Walk the concurrent statements of a design as regions, with their sensitivity and their passive, postponed and guarded flags, and the sequential statements of a process or subprogram with their source lines. [#829](https://github.com/ru551n/yavs/issues/829)
- **Connectivity.** Walk the drivers, contributors, loads, simulated net, basic signals, pending transactions, resolution function and kind of a signal, with callbacks on a transaction, a force and a release, whichever side the force comes from. [#830](https://github.com/ru551n/yavs/issues/830)
- **Declarations.** Find aliases, files, implicit signals such as `'stable`, components and configuration specifications, subprograms with their parameters and bodies, package bodies, libraries and use clauses, and read user attributes, including one whose value depends on a generic. [#831](https://github.com/ru551n/yavs/issues/831)
- **Phases and control.** `vhpiPhaseP`, tool and elaboration phase callbacks, `vhpi_control(vhpiReset)` with its callbacks ([resetting a simulation](https://yavs.readthedocs.io/en/v0.12.0/vhpi.html#resetting-a-simulation)), and callbacks for VHPI errors, Ctrl-C and debugger stops. With plugins loaded, Ctrl-C ends the run cleanly between cycles. Analysis, quiescence, save and restart stay out and return the standard's errors. [#832](https://github.com/ru551n/yavs/issues/832)
- **Values.** Read and write whole records and arrays of records as raw data and small physical values, convert values with `vhpi_format_value`, and use `vhpi_protected_call` on protected objects. [#833](https://github.com/ru551n/yavs/issues/833)
- **The seed.** `vhpi_get(vhpiRandomSeedP, tool or NULL)` reads the seed of a `--shuffle` run. [#983](https://github.com/ru551n/yavs/issues/983)

# Language and foreign code

- **Generic maps in protected type headers (VHDL-2019).** `type t is protected generic (w : integer); generic map (w => 4); ... end protected;` declares a type ready to use, with constant, type, subprogram and package generics. Outside what the standard allows, a generic clause or map in a protected type is now a clear error instead of being accepted or ignored. [#445](https://github.com/ru551n/yavs/issues/445)
- **Assert message formats.** `SetVhdlAssertFormat` sets the format of the messages of a severity (`{s}`, `{S}`, `{r}`, `{t}` with optional alignment, width and time unit, and `{i}`), `GetVhdlAssertFormat` returns it, and an invalid format gives `Valid => false`. [#922](https://github.com/ru551n/yavs/issues/922) [#982](https://github.com/ru551n/yavs/issues/982)
- **Foreign libraries that take fat pointers.** `--load=LIB:args=fat-pointer` loads a library whose C functions take an unconstrained array as a pointer to its data and bounds pointers, for that library only ([the fat-pointer layout](https://yavs.readthedocs.io/en/v0.12.0/vhpi.html#the-fat-pointer-layout)). [#928](https://github.com/ru551n/yavs/issues/928)
- **Foreign calls during elaboration.** A foreign function can give a signal its initial value, and `yavs elab` accepts `--load` like `yavs run`, so such a design elaborates on its own. [#928](https://github.com/ru551n/yavs/issues/928) [#943](https://github.com/ru551n/yavs/issues/943)

# vunit-yavs

The package and the extension now share the yavs version, and every release attaches them ([options](https://yavs.readthedocs.io/en/v0.12.0/vunit-yavs.html), [using yavs from VUnit](https://yavs.readthedocs.io/en/v0.12.0/vunit.html)). [#903](https://github.com/ru551n/yavs/issues/903)

- **Debug and watch one test.** `--yavs-interactive` runs a test at the console with the `vunit_*` commands, `--yavs-surfer` shows its waves live, and killing `python run.py`, even with SIGKILL, now ends the simulation so a debugged test no longer keeps the port. [#904](https://github.com/ru551n/yavs/issues/904) [#876](https://github.com/ru551n/yavs/issues/876) [#940](https://github.com/ru551n/yavs/issues/940)
- **Coverage from the run script.** `enable_coverage`, `--yavs-cov=LETTERS`, `results.merge_coverage()`, `--yavs-cov-html` and `--yavs-cov-fail-under` (per kind too) collect, merge and check coverage ([coverage from VUnit](https://yavs.readthedocs.io/en/v0.12.0/vunit.html#collect-coverage)). `--yavs-cov-exclude`, `--yavs-cov-config`, `--yavs-cov-below`, `--yavs-cov-detailed`, `--yavs-cov-embed-sources` and the export flags `--yavs-cov-json`, `--yavs-cov-lcov`, `--yavs-cov-sonarqube` and `--yavs-cov-cobertura` reach the new reports, and `yavs.cov_kind` takes the new kinds. [#877](https://github.com/ru551n/yavs/issues/877) [#883](https://github.com/ru551n/yavs/issues/883) [#1020](https://github.com/ru551n/yavs/issues/1020)
- **Lint after compiling.** `--yavs-lint` runs `yavs lint` on the project's libraries, and a finding of severity error fails the compile step ([with VUnit](https://yavs.readthedocs.io/en/v0.12.0/lint.html#with-vunit)). [#895](https://github.com/ru551n/yavs/issues/895)
- **Faster, safer compiling.** `--parallel-compile` and `--batch-compile` work, and the file names of a batch go on the command line, so names with accents are safe on every platform. [#114](https://github.com/ru551n/yavs/issues/114)
- **Native libraries and embedded Python.** A VUnit package can call a native library, and Python embedded in it, from VHDL through foreign subprograms ([native libraries](https://yavs.readthedocs.io/en/v0.12.0/vunit.html#vunit-native-library)). `native_library_hooks(library, args="fat-pointer")` picks the layout. [#120](https://github.com/ru551n/yavs/issues/120) [#928](https://github.com/ru551n/yavs/issues/928) [#943](https://github.com/ru551n/yavs/issues/943)
- **Threads under the token server.** A simulation starts its extra threads only when lent its first token and uses at most 4 threads unless told otherwise, so a large `-p` no longer creates thousands of idle threads. A server that cannot be reached is a warning ([`W0118`](https://yavs.readthedocs.io/en/v0.12.0/error-codes.html#w0118)) and the run continues on one thread ([sharing CPU](https://yavs.readthedocs.io/en/v0.12.0/libraries.html#vunit-token-server)). [#878](https://github.com/ru551n/yavs/issues/878) [#879](https://github.com/ru551n/yavs/issues/879)
- **Clear refusals.** A wrong flag combination or setup prints the message alone with a non-zero status, instead of a Python traceback. `--yavs-debug` or `--yavs-interactive` with `--yavs-cov`, and `--yavs-surfer` with `--elaborate`, are refused before anything runs. [#998](https://github.com/ru551n/yavs/issues/998)
- **Run scripts you did not write.** `VUNIT_YAVS_MAX_THREADS` caps the threads for scripts that parse their own command line ([run scripts you do not write](https://yavs.readthedocs.io/en/v0.12.0/vunit-yavs.html#run-scripts-you-do-not-write)). [#879](https://github.com/ru551n/yavs/issues/879)

# Bug fixes

**A wrong result, fixed.** A file whose unit was defined again by a later file brought its old copy back in a run, so stale values or the wrong architecture could run, with no message, depending on the order of the design's files. A run now uses the units the library holds. A unit that only worked through the old copy now fails with the error of its analysis, and a primary unit replaces a unit of another kind with the same name, so a package can take the name of an earlier entity. [#1054](https://github.com/ru551n/yavs/issues/1054)

**Language and elaboration: more designs run**

- Association in parts for generics and unconstrained record formals, and port maps that convert part of a formal. [#816](https://github.com/ru551n/yavs/issues/816) [#617](https://github.com/ru551n/yavs/issues/617) [#618](https://github.com/ru551n/yavs/issues/618)
- A non-static subscript as an `in` port actual, such as `queue(index)`. [#880](https://github.com/ru551n/yavs/issues/880)
- `bus` and `register` record signals with a record resolution function. [#595](https://github.com/ru551n/yavs/issues/595)
- A package with a generic map that has a body, and file objects in blocks and generates. [#605](https://github.com/ru551n/yavs/issues/605) [#966](https://github.com/ru551n/yavs/issues/966)
- Protected methods called directly during elaboration, in constants, generics and bounds, and recursive designs that pass a constant down as a generic. [#912](https://github.com/ru551n/yavs/issues/912) [#913](https://github.com/ru551n/yavs/issues/913)
- An incremental binding that names only some generics or ports. [#820](https://github.com/ru551n/yavs/issues/820)
- An impure function under `others` runs once per element, so each gets its own object. [#907](https://github.com/ru551n/yavs/issues/907) [#909](https://github.com/ru551n/yavs/issues/909)
- A static generic actual outside its subtype no longer stops the design when its generate branch is configured off. [#910](https://github.com/ru551n/yavs/issues/910)
- A protected type with no body is reported once, and selecting a generic through an object of a generic protected type says it is a generic. [#968](https://github.com/ru551n/yavs/issues/968) [#969](https://github.com/ru551n/yavs/issues/969)
- PSL `&&` in a sequence now runs instead of being skipped. [#841](https://github.com/ru551n/yavs/issues/841)
- An aggregate target can have composite elements in every form: record signals, arrays of records or arrays, matrices, and guarded assignments through them, with each length checked. [#1011](https://github.com/ru551n/yavs/issues/1011)
- A design is no longer rejected when an unused architecture in one of its files reaches a package the design also uses from a later file, which gave `expected T, found T`. [#991](https://github.com/ru551n/yavs/issues/991)
- A `wait until` condition with an edge test after a function call, such as `wait until f(x) and rising_edge(clk)`, calls the function at every event of its signals, so an impure function no longer misses calls. [#1022](https://github.com/ru551n/yavs/issues/1022)
- `'path_name` and `'instance_name` of packages read as they should: local packages and instances, library packages named by themselves, generic packages and items of nested packages, some of which stopped with an internal error. [#1007](https://github.com/ru551n/yavs/issues/1007) [#1010](https://github.com/ru551n/yavs/issues/1010)
- An external name of a constant whose subtype has another length than the constant is `E2121`, as for a signal. [#1006](https://github.com/ru551n/yavs/issues/1006)

**One file, however its path is spelled.** Files reached through `..` or a symlink are now the same file everywhere: analysis, `elab` and `run` reuse their units, and a valid design is no longer rejected when one command names a file both ways; a library directory named twice no longer waits for its own lock; debugger breakpoints and `--source-map` entries match, and a breakpoint removed in the editor is removed; lint waivers, exclusion `files` rows, `yavs cov report --root` and `yavs lint`'s library lookup all follow the link. [#1016](https://github.com/ru551n/yavs/issues/1016) [#1031](https://github.com/ru551n/yavs/issues/1031) [#1032](https://github.com/ru551n/yavs/issues/1032) [#1036](https://github.com/ru551n/yavs/issues/1036) [#1037](https://github.com/ru551n/yavs/issues/1037) [#1038](https://github.com/ru551n/yavs/issues/1038) [#1040](https://github.com/ru551n/yavs/issues/1040) [#1041](https://github.com/ru551n/yavs/issues/1041) [#1044](https://github.com/ru551n/yavs/issues/1044)

- Signal parameters: `null` waveform elements, aggregate targets of their parts, and `'driving` and `'driving_value` on them and on parts of a signal. [#602](https://github.com/ru551n/yavs/issues/602) [#610](https://github.com/ru551n/yavs/issues/610) [#615](https://github.com/ru551n/yavs/issues/615)
- Resolution functions declared in blocks and generates see the right constants and generics, and predefined functions resolve signals through aliases. [#817](https://github.com/ru551n/yavs/issues/817) [#608](https://github.com/ru551n/yavs/issues/608)
- An alias can name a subtype attribute such as `a'element`, a file declaration can use a generic file type, and a package instance in an architecture can hold a file object. [#914](https://github.com/ru551n/yavs/issues/914) [#915](https://github.com/ru551n/yavs/issues/915) [#925](https://github.com/ru551n/yavs/issues/925)
- Package subtype bounds are evaluated once, a constrained array parameter of a function called during elaboration has its own bounds, and `'path_name` of a variable in a protected type names the object that holds it. [#848](https://github.com/ru551n/yavs/issues/848) [#906](https://github.com/ru551n/yavs/issues/906) [#916](https://github.com/ru551n/yavs/issues/916)
- A PSL boolean of type `bit` or `std_ulogic` is accepted in a VHDL-1993 file. [#911](https://github.com/ru551n/yavs/issues/911)

**Language: now refused.** An index constraint outside its index subtype is reported for unused declarations too, and a package with a generic map and no generic clause gets an ordinary error instead of an internal one. [#847](https://github.com/ru551n/yavs/issues/847) [#967](https://github.com/ru551n/yavs/issues/967) Items a declarative part does not list, and in VHDL-1993 port actuals the standard does not allow, are errors. [#867](https://github.com/ru551n/yavs/issues/867) [#926](https://github.com/ru551n/yavs/issues/926)

**Debugger and console**

- `quit`, `restart`, Ctrl-D and a disconnect work from a stop in an endless loop in a subprogram, and Ctrl-C at the prompt pauses the run again. [#918](https://github.com/ru551n/yavs/issues/918) [#932](https://github.com/ru551n/yavs/issues/932)

- A subprogram with unconstrained parameters no longer causes an internal error under `--dap`, nor does a design with no process in a debug session. [#863](https://github.com/ru551n/yavs/issues/863) [#995](https://github.com/ru551n/yavs/issues/995)
- Conditions can compare `unsigned` and `signed` with numbers and read generics, and are checked when you set them. [#935](https://github.com/ru551n/yavs/issues/935) [#970](https://github.com/ru551n/yavs/issues/970) [#957](https://github.com/ru551n/yavs/issues/957)

- The Restart button of an attached session restarts the run in place. [#963](https://github.com/ru551n/yavs/issues/963)
- `break list` shows the line a breakpoint stops at, a failed `break` keeps its number, `deposit -out` is an error, and `drivers` of a port with no driver shows no driving value. [#956](https://github.com/ru551n/yavs/issues/956) [#960](https://github.com/ru551n/yavs/issues/960) [#974](https://github.com/ru551n/yavs/issues/974)
- Flags of a test runner's console command reach `yavs run`, and its output comes after the commands before it. [#933](https://github.com/ru551n/yavs/issues/933) [#947](https://github.com/ru551n/yavs/issues/947)

**Surfer.** One that stops answering no longer ends `--surfer` for the session, and the view catches up when it answers again; arrays show their elements and a restart clears the old markers. [#952](https://github.com/ru551n/yavs/issues/952) [#876](https://github.com/ru551n/yavs/issues/876)

- `vhpi_printf` and `vhpi_assert` write ISO-8859-1 text as UTF-8, and a callback's `obj` stays valid after the plugin releases its handle. [#984](https://github.com/ru551n/yavs/issues/984) [#273](https://github.com/ru551n/yavs/issues/273)

# Known limits

- **Long runs of whole processors are slower** than on the established open-source simulator, while most testbenches are faster ([performance](https://yavs.readthedocs.io/en/v0.12.0/performance.html#long-runs-of-whole-processors)). The latest head-to-head came out slightly worse than the previous one, and we do not know why yet.
- **Conformance is evidence, not proof.** The [conformance report](https://yavs.readthedocs.io/en/v0.12.0/conformance.html) attached to this release lists every suite, including the tests that do not pass yet and the parts of VHPI whose call traces still differ.
- **VHPI is partial.** Save and restart, some callbacks and some smaller objects are out: [#978](https://github.com/ru551n/yavs/issues/978), [#979](https://github.com/ru551n/yavs/issues/979).
- **The extension is a download.** It is attached to this release and is not on the Marketplace or Open VSX yet.
