yavs 0.16.0 builds from source on macOS on Apple silicon, makes the common numeric and Synopsys operators much faster in compiled code, and fixes a wrong result of signed `mod`.

- **macOS on Apple silicon:** a build from source works, foreign subprograms use that platform's calling convention, and VHPI plugins load.
- **Faster numeric operators:** most `numeric_std` operators, including `*`, `/`, `rem`, `mod`, `abs`, unary minus, `?=` and the other matching relations, `maximum`, `minimum` and `std_match`, now run in compiled code at about the cost of an addition.
- **Faster Synopsys packages:** the operators and conversions of `std_logic_arith`, `std_logic_unsigned` and `std_logic_signed` run as fast as their `numeric_std` counterparts.
- **Faster registers and records:** designs with many narrow registers, and records assigned as a whole, simulate faster when nothing asks the event history of those signals.
- **Bug fix (#1109):** signed `mod` with a weak `H` as the dividend's sign element now gives the IEEE package's result.



# Features

- A build from source on macOS on Apple silicon now compiles, and foreign subprograms loaded with `--load` follow that platform's calling convention.
- VHPI plugins load on macOS on Apple silicon: the `yavs` executable exports the `vhpi_*` functions, and a plugin built with `-undefined dynamic_lookup` binds to them.

# Bug fixes

- Signed `mod` in `numeric_std` now treats a dividend whose sign element is a weak `H` as the IEEE package body does, instead of as `1`. (#1109)

# Miscellaneous

- Assigning a whole record signal, or an aggregate, that changes at every clock runs faster in compiled code. (#1110)
- Designs with many narrow registers simulate faster when nothing asks the event history of those signals. (#1111)
- The `*` of `numeric_std` vectors with a product of more than 64 elements, and `rotate_left`, `rotate_right`, `rol` and `ror` of vectors longer than 64 elements, run much faster, in compiled code as well as in the interpreter.
- The `*` of a `numeric_std` vector and an integer, in either order, runs much faster, in compiled code as well as in the interpreter.
- The `*` of two `numeric_std` vectors with a product of up to 64 elements runs much faster in compiled code.
- The `/`, `rem` and `mod` of `numeric_std` vectors, and of a vector and an integer in either order, run much faster, in compiled code as well as in the interpreter, also for vectors of more than 64 elements.
- The `numeric_std` functions `maximum` and `minimum`, the matching relations `?=`, `?/=`, `?<`, `?<=`, `?>` and `?>=`, and `std_match` of vectors run much faster, in compiled code as well as in the interpreter.
- The `to_01` conversion of short vectors, in `std_logic_1164` and `numeric_std`, runs much faster in compiled code and the interpreter.
- The arithmetic operators, comparisons, `conv_integer` and the `conv_*` conversions of `std_logic_arith`, `std_logic_unsigned` and `std_logic_signed` now run as native operations, and compiled code computes them in place on short vectors, so designs written with these packages simulate faster.
- Unary minus of a `signed` vector in `numeric_std` runs much faster in compiled code and the interpreter.
- `abs` of a `signed` vector in `numeric_std` runs much faster in compiled code and the interpreter.
