yavs 0.17.0 adds `--threads=auto`, changes how `--tier=auto` compiles by default, and makes large designs and multi-threaded runs faster.

- **`--threads=auto`:** yavs picks the thread count itself, using more threads only while they make the simulation faster, and remembers the choice for each command line. The test runner package runs every simulation that way. (#884)
- **Changed default, `--tier-compile`:** under `--tier=auto` a run now waits while a function compiles (`--tier-compile=wait`), so a simulation never keeps more cores busy than `--threads`. Before, a compile thread ran alongside it, and as many simulations as cores could lock up the computer. `--tier-compile=background` brings the old behaviour back, at the lowest priority of the system. A first short run that waits can be a little slower than before while it compiles; later runs use the cache. (#1123)
- **Faster large designs:** records, arrays of records and matrices passed to subprograms go to copies made for their shapes, and the generated code of loops and process activations does less work.
- **Faster multi-threaded runs:** designs that gain from `--threads` run faster on several threads, and `--threads=N` costs less on designs whose processes are too small to share out.
- **Faster registers and array functions:** designs that move data through registers, flat or in records, and functions that return arrays simulate faster. (#1118, #1122)
- **Bug fix:** a block guard whose condition names a signal of an instance elaborated after the block is evaluated again whenever such a signal is active. (#1120)
- **Bug fix:** analysing or running a library with and without `--relaxed` in turn no longer analyses it again every time. (#803)
- **Bug fix:** a token server that refuses the secret by resetting the connection is reported as an error, not as a server out of reach. (#1124)
- **Bug fix:** a design whose elaboration calls pure functions that read package state no longer lowers and compiles itself again on the first run that answers them from the cache.

# Features

- `yavs run --threads=auto` uses more threads only while they make the simulation faster, and the test runner package runs every simulation that way under its token server. (#884)
- Under `--tier=auto` a run now waits while a function compiles, so as many simulations as cores no longer lock up the computer with one busy compile thread each; `--tier-compile=background` (sim option `yavs.tier_compile` in the test runner package) keeps the old compile thread alongside the run, now at the lowest priority of the system. The first short run of a design that waits compiles only what it spent its compile time in, so it loses little to the compiles; the runs after it compile the rest for the cache. (#1123)

# Bug fixes

- A unit that uses another unit whose analysis depends on `--relaxed` now keeps its analysed form for each setting, so analysing or running a library with and without `--relaxed` in turn no longer analyses it again every time. (#803)
- Under `--threads`, `--tier=auto` judges its compile decisions by the time of the simulation itself, so the helper threads no longer make a run look slower than it is. A short test that ran before links the compiled code of its own hot processes from the start. (#884)
- A block guard whose condition names a signal of an instance elaborated after the block, or holds an index outside its range that is never evaluated, is now evaluated again whenever a signal of the condition is active. (#1120)
- A token server that refuses the secret by resetting the connection is reported as an error, as one that closes it is, instead of a server out of reach. (#1124)
- A design whose elaboration calls pure functions that read package state no longer lowers and compiles itself again on the first run that answers those calls from the cache.

# Miscellaneous

- Designs that gain from `--threads` run faster on several threads, and `--threads=auto` picks the faster thread count from the first trial of a run and starts that trial on time on designs whose delta cycles are slow. `--threads=N` costs less on designs whose processes are too small to share out. (#884)
- Designs that move data through registers, flat or in records, simulate faster, most of all where nothing waits for the registers in between. (#1118)
- Calls of functions that return arrays run fewer instructions in compiled code: no check of a result against its own bounds, a constant target checked against its known length, and the size of a local array computed without a layout in memory. (#1122)
- Cold runs of testbenches with many protected objects or one very large process elaborate and start faster.
- Compiled code of large designs keeps the rare ways of signal reads and of `numeric_std` operations out of line, so fewer branches are taken and the branch predictor of the processor keeps up better.
- Large designs that pass records, arrays of records or matrices to subprograms simulate faster: those calls go to copies of the subprograms made for the shapes of their arguments, and the generated code of loops and process activations does less work.
- The compile thread's trace (`YAVS_AUTO_TRACE`) names the function it was still compiling when the run ended.
- Warm runs link the compiled code of copies of subprograms whatever order the copies were made in.
- `YAVS_VERIFY_IR` now also checks that no IR register is read before it is written and verifies each function after inlining and optimising, as debug builds do.
