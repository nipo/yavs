yavs 0.13.0 rejects more code that the standards do not allow, each with a diagnostic that names the construct and the fix, adds a warning for a design unit declared twice in one file, and fixes unconstrained deferred constants of generic packages and the perf map of compiled code.

- **Stricter language checks (breaking):** nine constructs that earlier versions accepted are now errors, listed under "Breaking changes" with the clause, the fix and, where one exists, the `--relaxed` switch.
- **Named-return calls and aggregate targets:** a `return r of t` call as the value of a `return` (`E1304`), and a nested aggregate inside an aggregate target of an array of arrays (`E1410`).
- **Names and type marks:** `T'base` as a type mark (`E1201`) and VHDL-2019 operators with anonymous parameter types in operator notation (`E1505`).
- **VHDL-1993 files:** an operation declared both implicitly and explicitly through use clauses is ambiguous (`E1302`); `--relaxed` takes the explicit one (`W1302`).
- **PSL:** declarations after `begin` (`E1241`, `--relaxed` gives `W1241`), a repeated declaration name (`E1101`), a comma between formal kinds (`E0002`) and an `or` of two properties (`E0013`).
- **Design units declared twice:** a file that declares the same unit twice gets warning `W0005` at the second copy.
- **Generic packages:** an unconstrained deferred constant of a generic package instantiated in an architecture, block, generate, process or function has the bounds and elements of its full declaration.
- **Profiling:** the perf map lists every function of generated code once with a readable name, also for cached code.


# Breaking changes

- A call of a VHDL-2019 function with a named return value (`return r of t`) as the value of a `return` statement is now error `E1304` (LCS-2016-072b: the call is allowed only where the context gives it a result subtype, and a `return` statement is not one of them). Assign the call to a variable of the result subtype and return that variable, or qualify the call, `t'(f(x))`. There is no `--relaxed` for this. (#33)
- An aggregate target with a nested aggregate as an element of an array of arrays, `((p, q), (r, s)) := m`, is now error `E1410` (LRM 2008 10.5.2.1 and 10.6.2.1: each element association of an aggregate target must be a name). Name whole rows, `(row0, row1) := m`, or assign the elements one by one. Targets of two-dimensional arrays and nested record targets are unchanged. There is no `--relaxed` for this. (#350)
- A PSL `sequence` or `property` declaration whose name is already declared in the same region (a constant, a port, another PSL declaration) is now error `E1101` (LRM 2008 12.3: two homographs may not be declared in one region). Rename one of the two. There is no `--relaxed` for this. (#1077)
- PSL formal parameters of different kinds separated by a comma, `property p (sequence s, boolean y)`, are now syntax error `E0002` (the PSL grammar separates kinds with `;` and names of one kind with `,`). Write `(sequence s; boolean y)`. There is no `--relaxed` for this. (#1078)
- A PSL `or` whose operands are both properties, `(a -> next b) or (a -> next[2] c)`, is now error `E0013` (IEEE 1076-2008 1.3.5 incorporates only the simple subset of PSL, and IEEE 1850 4.4.4 makes the left operand of `or` a Boolean). Rewrite it with a Boolean operand, or as two directives. An `or` with a Boolean operand still runs. There is no `--relaxed` for this.
- A PSL `sequence` or `property` declaration written after `begin` is now error `E1241` (LRM 2008 3.3.2 and 11.1: they are declarations of the architecture or block, and only PSL directives are concurrent statements). Move it before `begin`, or pass `--relaxed` to accept it with warning `W1241`.
- A VHDL-2019 user operator with parameters of an anonymous type (`function "<" (a : type is private; b : a'subtype)`) used in operator notation, `r < r`, is now error `E1505` (LCS-2016-016, 6.5.7.1: the anonymous types are bound through a parameter association list, which operator notation does not have). Call it in function notation, `"<"(r, r)`, which still works. In operator notation such an operator no longer competes with the predefined operators of other types. There is no `--relaxed` for this.
- In a VHDL-1993 file, an operation declared implicitly by one package and explicitly by another, both made visible by use clauses (`=` on `std_logic_vector` with `std_logic_1164` and `std_logic_unsigned`), is now ambiguous at its uses, error `E1302` (LRM 1993 10.4 and 10.5; only VHDL-2008 12.4 lets the explicit declaration win). Analyse the file with `--std=2008`, or narrow the use clauses. `--relaxed` uses the explicit declaration, with warning `W1302`.
- `T'base` used as a type mark, as in `integer'base'(5)`, `new word'base'("1010")`, `variable v : integer'base` or the conversion `integer'base(x)`, is now error `E1201` in a VHDL-1993 or VHDL-2008 file (LRM 2008 16.2.2: `'base` is allowed only as the prefix of another attribute, such as `integer'base'high`). Name the type directly, `integer'(5)`. A VHDL-2019 file still accepts it. There is no `--relaxed` for this.

# Features

- A design file that declares the same design unit twice now gets warning `W0005` at the second copy, naming the unit: the units of a file are analysed in textual order, so the second replaces the first, and a unit between them that names it is obsolete. (#1053)

# Bug fixes

- The perf map written for `perf report` (`YAVS_CLIFT_PERFMAP`, `YAVS_LLVM_PERFMAP`) now lists every function of generated code once, with its real size and a readable name (the process by instance path, or the subprogram), also for code linked from the compilation cache and under `--tier=clift`, so a profile of a warm run attributes compiled code per process. (#1074)
- An unconstrained deferred constant of a generic package instantiated in an architecture, block, generate, process or function (also inside another instance) now has the bounds and elements of its full declaration, in every execution tier, instead of a "not implemented" error (and, before that, a `'length` of 1); reading its bounds before its full declaration is elaborated is the same run-time error as in a package. (#1079)
