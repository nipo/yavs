yavs 0.18.0 removes the LLVM tier, so Cranelift is the only compiled tier, and makes the first runs and later runs of tests that wait for compiles faster.

- **Breaking, LLVM tier removed:** `--tier=llvm` and `--tier=auto3` stop with error E0120; `--tier=auto` (the default) and `--tier=clift` use Cranelift.
- **Faster `--tier-compile=wait`:** the first run no longer stops to compile a process it has hardly run, and later runs compile what the rest of the run repays, busiest functions first.
- **Faster `--threads`:** `--threads=N` and `--threads=auto` spend less time deciding where a batch of processes runs. (#884)
- **Faster array functions and signal assignments:** functions that return arrays of vectors or records, and assignments of a whole computed value to a signal, simulate faster. (#1122)
- **Faster first runs:** a library unit analysed from source is stored for the next testbench, and testbenches that use protected types from a library elaborate faster.
- **Remembered runs follow response files:** what `--threads=auto` and the default tier remember of a test's last run now follows the arguments inside a response file.

# Breaking changes

- The LLVM tier and `--tier=auto3` are removed: Cranelift is the compiled tier (`--tier=auto`, the default, and `--tier=clift`). `--tier=llvm` and `--tier=auto3` now stop with error E0120, which says so, and a build from source no longer has an `llvm` feature.

# Miscellaneous

- `--threads=N` and `--threads=auto` spend less time deciding where a batch of processes runs, so designs of many small processes gain more from the threads. (#884)
- Functions that return an array of vectors or records, such as one stage of an adder tree over an array of `signed`, are called with less overhead and simulate faster.
  Compiled code drives a signal assigned a whole computed value, such as `q <= a + b;` or `l1 <= reduce(t);`, straight from that value, which makes such assignments cheaper. (#1122)
- A run that has to analyse a library unit from source (its stored analysis was missing or out of date) now stores it, so the next testbench that uses the unit starts faster.
- The first run of a testbench that uses protected types from a library elaborates faster: it no longer reads every expression of the libraries to find which protected variables are asked their names.
- Under the default `--tier-compile=wait`, a later run of a program also compiles a process whose own running time is small when the subprograms it calls, which wait for it, would repay the compile.
- Under the default `--tier-compile=wait`, the first run of a program no longer stops, once it has passed a second of simulation, to compile a process it has hardly run (such as a test sequencer whose time goes to the subprograms it calls), so such tests are not held up compiling code that does not pay back.
- Under the default `--tier-compile=wait`, the runs after the first compile only what the rest of the run is expected to repay, the busiest functions for their compile time first, and keep compiling to about a quarter of a run's time, so short tests that run again stop much less for compiles.
- What `--threads=auto` and the default compiled tier remember of a test's last run now follows the arguments inside a response file too, leaving out only the seed and output path a test runner gives each run: a VUnit test keeps its memory whatever its seed, and starts afresh when its flags or generics change.
