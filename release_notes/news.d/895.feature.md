`yavs lint` reports what can be proved wrong about a design before it is simulated: a process that can never suspend, a function that can fall through, unreachable statements, vector width mismatches, indexes out of range and division by zero, with configuration, waivers and JSON, SARIF, JUnit, Code Climate and SonarQube reports. Advisory, experimental and policy rules (latches, multiple drivers, combinational loops, state machines, clock and reset crossings, and more) run when a configuration asks for them, and `--facts` writes state machines and clock and reset domains as JSON. `exclude` in the configuration leaves files and directories out.
A waiver can turn rules off for whole directories and file patterns: `rule`, `files` and the new `files_exclude` each take a list, a plain directory covers everything under it, patterns are relative to the waiver file, `files_exclude` wins over `files`, and a pattern that covers no file gets a warning. `yavs lint` reads the files to check from `file_list` in `yavs-lint.yaml`: paths, directories and globs, relative to the working directory, checked as well as the files on the command line. An entry that gives no file stops the run naming it; `--no-file-list` leaves the list out.
`yavs lint` is a static analysis tool, not a style guide or formatter: a key, rule or rule group it does not know in `yavs-lint.yaml` or `yavs-lint-waivers.yaml` is error E0134, every one listed with its line in one run and a suggestion for a near name, so a misspelled `files` or `lines` cannot widen a waiver. A configuration written for a formatter or style guide must have those sections removed.
